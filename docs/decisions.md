# 关键设计决策（ADR）

> **这些是"为什么这么选"的记录。**
>
> 代码能告诉你**是什么**，测试能告诉你**对不对**，但**"当初为什么不选另一条路"**
> 只有这里说得出。而这一条恰恰是最容易丢的 —— 三个月后，代码还在，
> 理由没了，于是同一个坑被重新踩一遍。
>
> ⚠️ **每做一个不可逆的选择，就在这里加一条。**
> 判断标准：**如果将来有人（包括你自己）会问"为什么不那样做"，就值得记。**

---

## ADR-001：绝不打包 Ginan 二进制

Ginan 自身是 Apache-2.0，但**它内含 JPL Ephemeris（GPL-3）**。

| | |
|---|---|
| ✅ 可以 | 以子进程方式调用 `pea`、替用户**下载** Ginan |
| ❌ 不可以 | 捆绑、再分发 `pea.exe` |

因为 GPL-3 是强传染性的 —— 一旦再分发含它的二进制，整个作品都要以 GPL-3 发布，
而 GPL-3 与我们的 Apache-2.0 不兼容。

**这条要反复强调**，因为"把 `pea.exe` 打包进 release、用户下载即用"
是个非常有诱惑力的改进，将来很可能有人（包括我）顺手就想做。

详见 [THIRD_PARTY.md](../THIRD_PARTY.md)。仓库里有两道结构性的闸门挡着它：
`.gitignore` 排除 `*.exe`，`.packinclude` 白名单里不列任何二进制。

## ADR-002：界面用 pywebview 而不是 Qt

理由：

1. 新手需要**好看的引导界面**，HTML/CSS 做这个远好于 Qt
2. agent 的事件流是生成器 → 天然映射到 SSE
3. **前端代码将来能复用于纯 Web 模式**，不锁死在 Qt 里
4. 打包小（Electron 起步 150 MB）

目前还没加 pywebview（只差约 40 行），因为它是唯一有平台怪癖的依赖。
先做「服务 + HTML」，界面两边**字节级相同**，推迟它不损失任何东西。

## ADR-003：源排序由实测决定，不由猜测决定

见 [ginan-facts.md 第一节「数据源可达性（实测）」](ginan-facts.md)。

**一个错的源比没有源更糟** —— 它会把 404 伪装成"文件还没发布"。

⚠️ 所以 `ginan-facts.md` 里每一条实测结论都**带日期**，并且写明"怎么复核"。
没有日期的实测结论等于没有保质期的食品。

## ADR-004：核心层不懂 Ginan

`core/` 里没有任何一行知道"Ginan"这个词。

所以将来要把这套内核拿去做别的领域（换个工具集做别的科学软件），
复制 `core/` 就行。

⚠️ 这条是**分层铁律**的一半：`core/` → `agent/` → `ginan/`，
依赖只能朝一个方向。`ginan/` 不许 import `core`。

## ADR-005：配置**载入官方示例**来改，而不是手写

**决定**：Ginan 的配置以 `ginan_agent/ginan/example_configs/` 里那份**官方示例**
为模板 —— `yaml.safe_load` 成 dict、改文件路径和档位、再 dump 回去。
手写构造保留给 PPP（`Workflow.example = None`）。

**为什么**（2026-09-24 实测）：

    同一份数据、同一个二进制、同一批先验产品，只有配置不同：
        手写 POD 配置    → 第 0 个历元 `dpotrf failed`，82 秒/历元，NaN 级联，崩
        官方示例（只改路径）→ 0 次失败，2.7 秒/历元，四个产物齐全

    手写那份缺的是整块骨架：`minimum_constraints`（基准定义 ——
    没有它法方程秩亏）、`orbit_propagation`（卫星受力模型）…

**手写 200 个键，错一个的样子是「配置看着正常、跑起来是 NaN」——
而那种错读代码发现不了。** 再走 17 遍就会错 17 遍。

**这条和 `config.py` 模块 docstring 拒绝的那个方案不冲突**：那里拒绝的是
**字符串模板**（静默漏替换 / 缩进改语义 / 无法静态检查），三条理由针对的都是
"字符串"。载入成 dict 之后三条都不成立。

| | |
|---|---|
| ✅ 走模板 | POD。`Workflow.example` 填文件名 |
| ⚠️ 仍手写 | PPP。它有实测数字背书（3.8/4.5 厘米那组），换它要连带重测 —— 那是独立的一轮 |

**怎么保证不偏离**：`scripts/check_toolchain.py` 里有一张**字面量白名单**，
把生成的配置和示例逐路径 diff，多一条少一条都红。
白名单本身也有"过期检查"（声明了却没发生的偏离也要报）。

**代价**：生成的 YAML 里没有注释了（`safe_dump` 不保留），所以表头
（`config.config_header`）成了唯一的说明，它必须带上"配置来源"那一行。

⚠️ 还留着一个口子：**PPP 仍是手写**。这是刻意保留的中间状态，
`Workflow.example` 那一栏就是它的标记 —— 加第 3 个工作流时必须在守卫里
（`test_workflow_declares_its_config_source`）写明它属于哪个世界。

（2026-09-27：加 `brdc2sp3` 时那条守卫**如期变红**了 —— 那是它在干活。）

## ADR-006：`compare_orbits` 是**工具**，不是工作流

| | |
|---|---|
| 决定 | 不进 `workflows.WORKFLOWS` 那张表；做成 `do_compare_orbits` 工具 |
| 日期 | 2026-09-27 |

**为什么不能塞进表里。** 读源码（`acsConfig.cpp:4427-4436`）：

```cpp
if (acsConfig.compare_orbits || vm.count("compare_orbits"))
{
    std::cout << "\n----- Orbit Comparator -----\n";
    tryGetFromOpts(acsConfig.sp3_files, vm, {"sp3_files"});
    compareOrbits(acsConfig.sp3_files);
    std::cout << "\n----- Orbit Comparator -----\n";
    exit(EXIT_SUCCESS);          // ← 就在这里结束
}
```

它在 `main` 的**顶部**、**在 `checkValidFiles` 之前**就 `exit()`。所以：

| `Workflow` 那一栏 | 对它成立吗 |
|---|---|
| `modes` | ❌ 没有 `process_modes` 这回事，流程压根没走到那儿 |
| `outputs` | ❌ 不写任何产物文件，结果打在 **stdout** |
| `needs` | ❌ 只要两个 SP3 路径，别的输入文件**一个都不校验** |
| `epoch_interval` / `run_timeout` | ❌ 没有历元循环 |
| `profiles` | ❌ 没有模型文件的概念 |

⇒ 硬塞进去，得给它编一组**不成立的值**。而"表里每一栏都该是真的"
是那张表存在的全部意义 —— 编出来的栏位会让下一个人以为它们有意义。

**它是"分析动作"，不是"处理流程"。** 用户的说法也不一样：
跑工作流是「帮我定个轨」，用这个工具是「**我这条轨道准不准**」。

**代价**：它不走 `config.build_config`（那个函数按 `Workflow` 分支），
自己载入 `compare_orbits.yaml` 这个模板。所以它是**唯一**一个
"用模板但不经过 `build_config`"的地方 —— 这一点在
`do_compare_orbits` 的 docstring 里写明了，免得下一个人去找它的 `Workflow` 行。

⚠️ 配套的一条：**送进去的我们自己的产物必须先修 `E*`**（见 `ginan-facts.md`
七点十四）。不修的话 Ginan 只读得到一个历元，报出来的数是
"1 个公共历元 / 1,800,000 米" —— 一个**看着像结果**的垃圾数。
修的是**副本**，原产物不动。

## ADR-007：SBAS 跑**固定的一份官方演示数据**，不接用户的站和日期

| | |
|---|---|
| 决定 | `Workflow.dataset` + `catalog.Dataset`；有它的工作流忽略调用方给的 `stations`/`day` |
| 日期 | 2026-09-27 |

**为什么不能像别的六条那样"某站某天去网上取"。**

SBAS 的改正信息（`.ems`）**没有公开的日常源** —— 它由 SBAS 运营方从地球同步卫星
播发，**播完就没了，不归档**。市面上没有"SBAS 的 IGS"这种东西。

⇒ 能拿到的只有**别人录下来的一段**。Ginan 官方录了
**2025-11-11（DOY 315）00:00–06:45、四个测站**，放在自己的 S3 桶里。

⇒ 所以 SBAS 在 app 里只能是「**跑一次官方演示**」。
   这不是偷懒，是**数据的物理性质** —— 和 `rt_ppp`（活流不归档）同一类，
   只是那一条连录像都没有（见路线图第四节）。

**代价（必须一起承担）**：

| | |
|---|---|
| ⚠️ 用户给的站和日期被**忽略** | 所以 `do_plan_run` 的回执里**必须**写明"用的是哪份数据、哪几个站"，并**要求转达** —— 不说的后果是他去结果里找自己的站，找不到，然后以为程序坏了 |
| ⚠️ **1.9 GB** 的下载 | 本项目最大的一次。`fetch_data` 已经要用户拍板，但这条要在**说辞里带上数字** |
| ⚠️ 三条 SBAS 工作流共享同一份数据 | 跑第二条时不会重下（文件按名字判"已经在了"） |

**为什么是三条工作流而不是一条带参数**：
`Workflow.modes` 的规矩是「每个工作流内部那组开关**定死的**，
不给模型自由组合的机会」（见 `workflows.py` 模块 docstring）。
而 `sbas.mode`（L1 / DFMC / PVS）恰恰是"配错了不报错、只是结果不对"的那种，
所以三条各写各的。

⚠️ 第四条 `sbas_example_pvs_rt` **没有条目** —— 它用 `sisnet://` + NTRIP 活流。

## ADR-008：不接电离层 —— 而且**「做不了」要分三种说**

| | |
|---|---|
| 决定 | 不加电离层工作流、不加电离层工具、**也不接** `outputs.ionstec` 那个替代品 |
| 日期 | 2026-09-27 |

### 为什么不做：**不是数据的物理性质，是上游那条路本身是坏的**

九次受控运行，没有一组配置能出产物（现场见 `ginan-facts.md` 七点十七）：
崩 / 段错误 / 堆损坏 / 解在第 4 个历元发散 / `IONEX` 恒 0 字节。

⚠️⚠️ 而且 —— `grep` 五个键打在**整个发行版**上（18 个官方示例、`Docs/`、
GinanUI 的默认配置、tests）：**0 命中**。**这个功能没有任何人走过。**

⇒ 这不是"我们还没开发"（**没做**），也不是"数据拿不到"（**做不了·数据**），
   而是第三类：**做不了·上游**。

### ⚠️ 所以「做不了」有三个不同的说法，不能混

| 说法 | 例子 | 用户该怎么办 |
|---|---|---|
| **没做** | 还没接的功能 | 等我们做 |
| **做不了·数据** | 实时流不归档（`rt_ppp`）、SBAS 电文不归档 | **永远也不会有**，别等 |
| **做不了·上游** | 电离层图 | 等**官方修**；或者换一条路（见下） |

把第三种说成第一种，用户会一直等我们；说成第二种，用户会以为换个数据源就行。
**两种都是错的。**

### 为什么连 `outputs.ionstec` 也不接

那个是**能出的**（1 小时 102,234 行，数值和滤波器状态逐位相同），
**看起来**正好是"换个方式实现电离层"。

**但它的数不是 TEC**：**28.7% 是负值**（TEC 不可能为负），
GPS 中位数 **3.97** 而 Galileo **21.07** —— 同一个电离层差 5 倍多。

原因是它是 PPP 滤波器内部的**斜向延迟估计**，把**差分码偏差的分配**吃了进去 ——
那正是单站 PPP 解不出来的自由度。

⇒ 接了它，用户会拿到一列**三成是负数、两套系统差 5 倍**的"电离层"。
**那比没有更糟** —— 本项目对"看着像结果的垃圾数"的立场见 ADR-006（`E*` 那条）。

⚠️ 所以第三个说法其实还有第四种情形，也要能和上面三种分开：

| | |
|---|---|
| **能做，但数不对，所以不做** | `ionstec`。**要说清楚是这一种**，不能含糊成"没做" |

### 代价（要一起承担）

| | |
|---|---|
| 用户问"能不能算电离层" | 如实说**做不了**，理由一句话：**官方这条路的代码没走通**（不是你的数据不行） |
| 守卫 | `check_toolchain.py` ㉑a 锁住"没有任何工作流打开 `ionosphere`"——**将来上游修好了，这条守卫会红**，那正是它的用途 |

## ADR-009：死字段的两种处置 —— `needs` 让它生效，`estimates` 变成**被核对的话**

| | |
|---|---|
| 决定 | 不给 `Workflow.estimates` 编行为；把它变成「一句守卫能核对的话」 |
| 日期 | 2026-09-27 |

### 怎么发现的

加 `fit_sp3_pseudoobs` 时要填 `estimates=("orbit",)`，于是问了一句
"它到底做什么"。**实测**（不是读代码）：

    把 `pod.estimates` 从 `("orbit",)` 改成 `()`，
    `config.build_config` 的产物 —— **一个字节都没变。**

根因：读它的三个函数（`_receiver_estimation` / `_satellite_options` /
`_satellite_estimation`）**只被 `_build_handwritten` 调用**，
而所有走模板的工作流（`example` 不是 `None`）都不经过那里。

⇒ **这一栏对 `pod` 和 `fit_sp3_pseudoobs` 从来没被读过。**

### 处置：**两种，不能一律"让它生效"**

`Workflow.needs` 当初也是死字段，处置是**让它真的生效**
（`plan_run` 按它筛）—— 那是**可以生效**的：它该决定"下哪些文件"。

`estimates` **没有可生效的东西**：模板里那些估计参数**本来就写好了**。
让 `_apply_workflow_delta` 再写一遍，等于把同一组值抄到第二处 ——
而两处迟早会漂（这个仓库反复吃过的亏）。

⚠️ 反面做法：让 `_build_from_example` 也去调那三个函数。
   那会把 **POD 调过的经验值**盖到 **fit_sp3 模板里的值**上 ——
   两者并不相同，那是**静默改掉官方示例的数值**。

⇒ 所以：**把它变成一句能被核对的话。**
   声明了 `orbit` 的工作流，产出的配置里**就得真的在估卫星轨道**；
   没声明的就**不许**在估。守卫 ㉓ 两向都核，并对照两个方向都真有工作流。

⚠️ 这样它的用途从"写配置"变成"**在换模板/改开关时抓住丢失**"——
   而那种丢失别处看不出来：**产物照样有（一堆 POS），只是没有了轨道**，
   退出码还是 0。

### 代价

| | |
|---|---|
| 它仍然不写任何配置 | 字段的 docstring 里**写明**了 —— 不留"以为它在干活"的空间 |
| 守卫会红 | 有人换模板、把 `orbit: {estimated: [true]}` 弄丢时会红 —— **那正是用途** |

## ADR-010：**Ginan 的源码一个字节都不改** —— 以及因此**必须说清的"停在哪"**

| | |
|---|---|
| 决定 | `ginan-dist/`（官方发行版）**只读**：不修 bug、不打补丁、不为调试加打印、不编译自己的副本 |
| 日期 | 2026-09-27 |

⚠️ **用户的原话是「ginan原本的不改」。** 上面那四条是**由它推出来的**，
   不是他逐条说的 —— 写宽了等于替他做决定。之所以照宽的记，是因为
   **"编译一个改了源码的副本"和"改源码"对下面的两条理由完全一样**
   （一样是派生作品、一样会让基准失效）。
   ⚠️ 如果将来有人只想**加一行打印再删掉**，那是**要重新问一次**的事，
      不要拿这条 ADR 当已经批过的许可。

### 为什么

| | |
|---|---|
| **许可证** | Ginan 是 **GPL-3**（它捆了 JPL Ephemeris），app 是 Apache-2.0 —— 改它就产生**派生作品**。见 ADR-001 |
| **基准会没** | 本项目所有结论的基准是「**官方示例逐字跑**」（POD 那 2.29 米就是拿它比的）。源码一改，"我们的数"和"官方的数"就不再可比，**全部对照实验作废** |
| **不是我们的事** | 「官方软件的问题不管」—— 修上游 bug 不在这个项目的范围内 |

⚠️ 允许的是**我们自己这边的一切**：`ginan-testdata-*/` 里的实验脚手架、
配置、解析脚本，随便写。**边界就是 `ginan-dist/` 那个目录。**

### 代价：有些问题**查不到底** —— 而且要把这件事说出来

有一类问题的答案**只在进程跑起来之后才存在**（运行时看设计矩阵里有没有那几列、
某个内部开关的实际取值）。拿它的办法只有两个：改源码加打印，或者上调试器。
⇒ **这两条都被本 ADR 挡掉了，所以那类问题到这里就停。**

已经因此停下的两条：

| | 停在哪 |
|---|---|
| ② SLR 段错误 | 推到「`ZIML` 进 SLR 流那一历元崩」，**根因没查**（要调试器） |
| ③ LEO 定轨 | 推到「观测对轨道的约束几乎为零」，**为什么没查**（要运行时观测） |

### ⚠️⚠️ 停的时候，**说法**比结论更要紧

停下来**不等于**"官方坏了"，也**不等于**"做不了"。三种说法见 ADR-008，
而这里最容易犯的错是**把"我们停在这"说成"上游是坏的"**：

| | 电离层（⑥） | LEO（③） |
|---|---|---|
| 证据 | 9 次受控运行**没有一组**出产物 + 全发行版 **0 命中** | 20+ 次**都跑完了**，只是结果不对 |
| 能说 | 「上游那条路是坏的」 | ❌ **不能这么说** |
| 该说 | 「等官方修」 | 「我们查到了边界，**再往下要改 Ginan，这件事不做**」 |

⇒ 所以停下来的每一条，都要**写清"边界在哪、再往下需要什么"** ——
   那是留给下一个人的全部价值。只写"做不了"，等于把这一轮的工作扔掉。

## ADR-011：凭据**只住软件目录** —— 因此碰 CDDIS 的代码必须自己带凭据

| | |
|---|---|
| 决定 | CDDIS 凭据只写 `userdata/_netrc`（+ `userdata/.netrc`）。**不**往家目录写第二份；凡是需要凭据的请求，必须走 `credentials.cddis_session()` / `cddis_get()` |
| 日期 | 2026-09-29 |

### 背景（实测，不是推理）

`requests` 在 `trust_env=True`（默认）时会**自己去读家目录**的 `.netrc`/`_netrc`，
而且跟跳转时还会**再补一次**。所以：

| 哪份凭据 | 谁认 |
|---|---|
| `userdata/_netrc`（本程序写的） | **只有** `cddis_session()` 那条路 |
| `C:\Users\<用户>\_netrc`（老位置） | `requests` 的一切隐式认证 |

⚠️ 后果：任何"拿普通会话去碰 CDDIS"的代码，都会退化成
**"只有这台机器恰好有份老 `.netrc` 时才通"**。
本机恰好有那份（迁移前留下的），所以这类 bug 在本机**是绿的**。

**已经咬到过一次**：侧栏的 CDDIS 探测用普通 GET，于是
「保存并验证」通过了、侧栏仍然显示「需要登录」，而且**永远不变**。
（详见 `ginan-facts` 七点二十五。）

### 考虑过的三个选项

| | 做法 | 结论 |
|---|---|---|
| **A** | 也往家目录写一份凭据 | ❌ **拒绝**。启动横幅承诺"所有东西都在自己的文件夹里"；用户也明确要求凭据放在软件目录内。而且会在**别人**的机器上留下凭据痕迹 |
| **B** | 让 `build_session` 一律 `trust_env=False`，堵住隐式 netrc | ❌ **没做**。它会**一并关掉环境变量代理**，而那是代码里已有的、写明了理由的选择。而且"隐式 netrc 生效、而 `read_paths()` 找不到凭据"这种情形实测基本不存在 —— `read_paths()` 本来就覆盖家目录，两者结论一致 |
| **C** | 该带凭据的地方，改用 `cddis_session()` / `cddis_get()` | ✅ **采纳** |

### 代价

⚠️ **今后每加一处"要碰 CDDIS 的代码"，都要自己记得走那条路** ——
普通会话在**开发机上**是能通的（那份老 `.netrc`），在**用户机器上**不通。
⇒ 所以补了一条守卫（`check_network.py` ⑳a）：它把两条路都换成假的，
断言 CDDIS 那条探测**一次都没走普通 GET**，而且别的源**必须**走普通 GET。

> 👉 判据必须能**模拟干净环境**。开发机上那份残留文件，
> 会让"我这儿是好的"变成一句什么都证明不了的话。

---


| 决策 | 理由 |
|---|---|
| 所有输入文件**平铺**在一个目录 | Ginan 的 `inputs_root` 是**前缀**，平铺后一行配置搞定 |
| 工具结果**必须截断**（默认 8000 字符） | `.TRACE` 能到 GB 级，会撑爆上下文 |
| 取消用**协作式**而非 `gen.close()` | 正在执行的生成器不能被 close |
| 拒绝工具时**仍要记一条 tool 消息** | API 要求每个 `tool_call` 恰好一条回复 |
| 模型列表**从接口现查**，不写死 | 模型名几个月就变，写死的列表一定过期 |
| `.gitignore` 里列了**必须提交**的文件 | 防止将来有人手滑加进去 |
| 观测文件名**不跟着改**，按内容重新命名落盘 | 用户从浏览器下的文件叫 `igs20(1).atx`，而配置里写的是精确文件名 |


## ADR-012：改正项**逐项**可配 —— 档位退成"默认值的来源"

| | |
|---|---|
| 决定 | 潮汐/电离层那 9 项改正**逐项**由用户定（设置面板里 9 个勾）。档位（基础/完整）保留，但降级成"默认值从哪来"；用户改过的项以**稀疏覆盖**存进 `config.json` |
| 日期 | 2026-10-01 |
| 代码 | `ginan/corrections.py`（注册表）、`config._model_options` / `_wanted_table_files`、`settings.corrections`、`/api/corrections` |

### 背景：用户的原话

> 海潮负荷、大气潮、二阶电离层、日月位置等等参数让用户来选择，你给选项

在那之前，这些参数**打包在两个档位里**，而界面上**根本没有这个开关**
（`grep profile` 前端 0 命中）——是 agent 在背后选的。用户既看不见，也改不了。

### 被否掉的四个方案

| 方案 | 为什么不行 |
|---|---|
| 只留两个档位（现状） | 用户既看不见也改不了，而**每一项都值几厘米到几十厘米**（实测见 `ginan-facts` 七点二十九） |
| 把 Ginan 那 3000 个配置项都暴露 | **全暴露等于没暴露**（`config.Profile` 的那条理由仍然成立） |
| 覆盖值存**整份 9 项** | 用户改一项，其余 8 项就被冻在那一刻；之后换档位**一项都不会跟着变**，而且看不出来 |
| 每跑一次问一遍 | 这是"我这台机器要用哪些改正"，不是"今天这个任务"的问题 —— 每跑一次都问就成了噪音 |

### 三条硬约束（都有守卫）

1. **不加参数＝不改行为**：`corrections` 为空时，生成的配置和不加这个字段时
   **逐字节相同**（㉖b 守着）——否则"新增逐项开关"会顺手改掉所有老用户的结果。
2. **开关和文件必须一起走**：打开一项时，它要的模型文件**必须同时写进配置**。
   只写开关 → Ginan 算不出来且**不报错**；只写文件 → 下了没用上（也是静默的）。
   ㉖c 就是守这个。
3. **只动它自己那一处**：关掉一项时，配置里**只有**它那一条路径该变
   （㉖a 用整体 diff 判，不是"看那一条变了没有"）——
   "顺手多改一处"和"少改一处"都会红。

### ⚠️ UI 上那行数字必须是**实测**的

用户会照着它决定"要不要下那 23 MB"。所以：

- 量过的写"实测：解移动 X 厘米"（`corrections.py` 的 `effect`）
- **没量过的一律写"没量过"** —— ㉖d 守着这条：标了 `measured` 就必须有数字，
  没标就必须**正好**是那三个字

⚠️ 一个必须说清的边界：那张表是**一个站（ALIC）、一天（2026-09-02）**的。
   海潮负荷在开阔海域的沿海站可以到几厘米，本站恰好在海湾里（表里径向 M2 只有 2.5 毫米）。
